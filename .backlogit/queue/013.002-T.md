title: Redact URL query and fragment tokens from navigation errors and queue logs
updated_at: 2026-11-11T02:03:12.4891651Z

Add teams.RedactURL and teams.RedactArgs in internal/teams/url.go and apply them to ChromeRunner.run navigation error wrapping in internal/browser/runner.go and batch queue argument logging in internal/cli/queue.go. Specification: (1) For a parseable HTTP/HTTPS URL with a non-empty host (u.Opaque == ""), clear u.User = nil, u.RawQuery = "", u.ForceQuery = false, u.Fragment = "", and u.Opaque = "" (keeping only normalized scheme://host/path). (2) For the malformed-URL / fallback path (when url.Parse fails, scheme is non-HTTP(S), u.Opaque != "", or u.Host == ""), do NOT simply slice up to ? or #; if the fallback cannot safely extract a clean scheme://host/path free of userinfo (@), query (?), and fragment (#), return a constant placeholder "[invalid-url]" (or strip any userinfo@ before the host in addition to stripping ?query and #fragment, and return "[invalid-url]" if any @, ?, #, or control character remains). Acceptance criteria: (a) ?p=secret-passcode, code=oauth, and #access_token=xyz never appear in RedactURL, RedactArgs, ValidateMeetingURL errors, ChromeRunner.Join navigation errors, or queue logs; (b) Unit tests in internal/teams/url_test.go explicitly test RedactURL with embedded userinfo credentials on both a valid URL (https://user:pass@teams.microsoft.com/meet/123?p=tok#frag) and a malformed URL (https://user:pass@teams.microsoft.com:badport/meet/123?p=tok), asserting that neither user, pass, tok, nor frag ever appears in the output.
