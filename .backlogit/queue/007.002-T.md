internal/capture: Session.Run(ctx, meeting) drives Meeting.Join then runs EnableCaptions and CaptureAudio concurrently (errgroup with a derived cancellable ctx) until ctx cancel, then flushes/closes. Because browser.CaptionSink has no error return, the sink writes to transcript.Writer.WriteEvent and, on a write error, records the first error into a shared field and cancels the session so capture stops instead of silently losing data; Session.Run returns that first error (or the flush/close error). Unit-test with a fake browser.Meeting: Join-before-capture ordering, caption events written, and write/flush failures propagate + cancel (no false success).
