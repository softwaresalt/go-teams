Update teams.ValidateMeetingURL in internal/teams/url.go and ChromeRunner.Join in internal/browser/runner.go to enforce initial-URL ingress validation before browser allocation and navigation: (1) non-loopback initial URLs require https:// and a hostname matching or dot-subdomain of trusted Microsoft Teams / SharePoint / Microsoft 365 domains (teams.microsoft.com, teams.live.com, teams.cloud.microsoft, sharepoint.com, microsoft.com, office.com, sfx.ms, aka.ms), while permitting http:// and https:// on loopback hosts (127.0.0.1, localhost, ::1) for local httptest.Server e2e and binary acceptance fixtures; (2) ChromeRunner.Join(ctx, meetingURL) in internal/browser/runner.go MUST call teams.ValidateMeetingURL(meetingURL) BEFORE calling r.run(ctx, opts, meetingURL) (before allocating a browser), returning a redacted validation error immediately on a disallowed URL without launching a browser; and (3) add a direct unit regression test in internal/browser/runner_test.go asserting that NewChromeRunner(...).Join(ctx, "https://evil.example.com/meet/123?p=secret") returns a validation error before browser allocation/launch and does not leak secret in the error string. Post-navigation HTTP/JS redirects inside Chromium (e.g. an allowed loopback endpoint redirecting to an untrusted remote host) are explicitly recorded as a documented residual risk because CDP-level redirect interception across federated Microsoft 365 / ADFS / Okta / Duo IdP sign-in flows would break enterprise authentication and is outside the ValidateMeetingURL contract.
