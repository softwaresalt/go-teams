Scope and approach:
1. In `internal/browser/recap.go`, add `extractRecapAudioJS`, configurable resource-limit package variables (`maxRecapAudioSourceBytes = 64 * 1024 * 1024` / 64 MiB compressed media blob cap, `maxRecapAudioDurationSec = 1800`, and `maxRecapAudioPCMBytes = 128 * 1024 * 1024` decoded PCM cap), and `captureRecapAudioFromTargets(ctx context.Context, cdpPort int, boundTargetID string, meetingURL string, w io.Writer) error` (invoked with `m.meetingURL` from `(*chromeMeeting).captureRecapAudio`):
   - Queries `listCDPTargets(cdpPort)`, resolves `ownedFrames` via `fetchOwnedFrames`, and filters targets strictly through `isTargetInCaptureScope(t, boundTargetID, ownedFrames)`.
   - Uses `recapExpectedIdentifiers(meetingURL)` (matching the transcript path's `targetMatchesIdentifiers` / `payloadMatchesIdentifiers` and `parseRecapPayloadForMeeting` discipline) to validate before extraction that the owned target/frame's `t.URL` and extracted media source URL / page metadata (`pageUrl`, `fileName`, `itemId`, `mediaUrl`) match the expected meeting recording identity when `recapExpectedIdentifiers(meetingURL)` is non-empty, skipping owned frames whose URL or media source mismatches the expected recording identity.
   - Enforces bounded decoding and transfer in `extractRecapAudioJS` and `captureRecapAudioFromTargets`: checks `Content-Length` and streamed reader byte count against `maxRecapAudioSourceBytes` before calling `decodeAudioData`, checks `audioBuffer.duration` (`<= maxRecapAudioDurationSec`) and decoded PCM byte length (`<= maxRecapAudioPCMBytes`) before allocating `Int16Array` / base64 chunks, transfers/decodes in bounded windows, and rejects recordings exceeding the cap with a clear structured error (`recap audio exceeds maximum supported size/duration`) before allocating unbounded PCM/base64 buffers.
   - Decodes each validated 44.1 kHz mono `int16` base64 PCM chunk with `decodeAudioPayload` (enforcing `maxRecapAudioPCMBytes`) and encodes to MP3 via `audio.NewEncoder(w, audio.SampleRate)` (`WritePCM` + `Flush()`).

Stage Approved Layered Resource-Cap Safety Contract (2026-11-11):

* Because Web Audio's `AudioContext.decodeAudioData` in Chromium does not expose a pre-decode streaming PCM API, the approved safety contract for `015-S` is the following 4-layer defense-in-depth design (with native Chromium `decodeAudioData` expansion on unknown-duration streams within the 64 MiB compressed cap recorded as an explicit, accepted residual risk isolated to the browser tab process):
  1. **Layer 1 (Pre-fetch known-duration check in `extractRecapAudioJS`)**: Before calling `fetch(mediaUrl)`, check `media.duration` (and `info.duration` / `info.durationSeconds`); if finite and `> 0` and (`> maxRecapAudioDurationSec` or `Math.ceil(duration * 44100) * 2 > maxRecapAudioPCMBytes`), throw `recap audio exceeds maximum supported size/duration` immediately before `fetch` (verified by `TestRecapAudioJSRejectsKnownOversizedDurationBeforeFetch`).
  2. **Layer 2 (Pre-decode compressed-source byte cap in `extractRecapAudioJS`)**: Check `Content-Length` and streamed `reader.read()` byte total against `maxRecapAudioSourceBytes` (`64 MiB`) and cancel the stream + throw `recap audio exceeds maximum supported size/duration` before calling `decodeAudioData` (verified by `TestCaptureRecapAudioRejectsOversizedRecordingExceedingResourceCap`).
  3. **Layer 3 (Post-decode / Pre-Int16Array & Pre-base64 PCM cap in `extractRecapAudioJS`)**: Immediately after `decodeAudioData` returns `buffer` and BEFORE allocating any `Int16Array` or base64 chunk, check `!Number.isFinite(buffer.duration) || buffer.duration > maxRecapAudioDurationSec || buffer.length * 2 > maxRecapAudioPCMBytes || outputLength * 2 > maxRecapAudioPCMBytes` and throw `recap audio exceeds maximum supported size/duration`.
  4. **Layer 4 (Pre-allocation CDP WebSocket frame-header and fragmented-message cap in `evalInCDPTarget` + Go payload validation)**: In `evalInCDPTarget` in `internal/browser/recap.go`, read WebSocket frames using `ws.ReadHeader(conn)` and enforce a transport byte limit `maxCDPBytes := int64(maxRecapAudioPCMBytes)*2 + 65536` (so when `maxRecapAudioPCMBytes = 8`, `maxCDPBytes = 65552`, which is `< 1 MiB` and `< 32 MiB`) BEFORE allocating the frame buffer (`if hdr.Length > maxCDPBytes || totalBytes+hdr.Length > maxCDPBytes { return "", fmt.Errorf("browser: cdp response exceeds maximum supported size/duration") }`), and then in `captureRecapAudioFromTargets` validate `SourceBytes`, `DurationSec`, and decoded base64 PCM bytes before MP3 encoding (verified by `TestRecapAudioCDPRejectsOversizedFrameHeaderBeforeBody` and `TestRecapAudioCDPRejectsOversizedFragmentedMessage`).
