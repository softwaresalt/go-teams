<!-- BEGIN:acceptance-criteria -->
1. internal/updater uses only the Go standard library and internal/version (zero new external dependencies in go.mod).
2. Updater.swap acquires <exe>.lock before removing stale <exe>.old and releases <exe>.lock only after renaming/rolling back <exe> and removing <exe>.old, serializing concurrent updates so one process cannot delete another process's <exe>.old rollback copy.
3. Dead-holder proof before stale eviction (Thread 1): Age (now - created_at > lockStaleAfter) is necessary but NEVER sufficient on its own to evict <exe>.lock. Before any stale eviction, the contender verifies that the recorded holder PID is no longer a live process via an injectable isProcessAlive func(pid int) bool probe (using OS process-existence checks and failing closed to alive = true whenever pid <= 0, metadata is unreadable/corrupt, or liveness cannot be disproved). If isProcessAlive(meta.PID) == true, the contender NEVER evicts <exe>.lock regardless of age and instead continues waiting until lockWaitTimeout expires and fails closed with ErrUpdateLocked, leaving <exe> and the holder's <exe>.lock untouched and removing its own temporary download file.
4. Exclusive control lock <exe>.lock.ctl serializing stale recovery and ownership changes with crash-safe lifecycle and bounded wait/release (Thread 2, Round-2 Thread 2): Both stale-lock eviction/replacement and lock release acquire a short-lived exclusive control lock <exe>.lock.ctl (os.OpenFile(lockPath+'.ctl', os.O_CREATE|os.O_EXCL|os.O_WRONLY, 0o600)) that writes and flushes the same JSON owner metadata (pid, 128-bit hex token, RFC3339Nano created_at) on creation, using a bounded wait budget (ctlLockWaitTimeout default 2s, ctlLockPollInterval default 10ms, injectable on Updater for deterministic tests) while respecting ctx.Done(). If <exe>.lock.ctl already exists with now - ctlMeta.CreatedAt > ctlLockStaleAfter (default 5s, injectable on Updater) AND ctlMeta.PID > 0 AND !isProcessAlive(ctlMeta.PID) (provably dead control-lock owner), the contender atomically renames <exe>.lock.ctl to <exe>.lock.ctl.stale.<token> (where <token> is the contender's freshly generated 128-bit hex token), removes the .stale file, and retries os.O_CREATE|os.O_EXCL acquisition within ctlLockWaitTimeout. If <exe>.lock.ctl metadata is unreadable/corrupt or isProcessAlive(ctlMeta.PID) is true, automatic control-lock eviction is refused; when ctlLockWaitTimeout expires, stale recovery fails closed with ErrUpdateLocked (naming <exe>.lock and <exe>.lock.ctl for manual operator cleanup after confirming all teams-cli update processes have exited), and primary-lock release aborts without unlinking <exe>.lock outside <exe>.lock.ctl (preserving mutual exclusion). Releasing <exe>.lock.ctl verifies its own ctlToken before os.Remove. During stale recovery, after acquiring <exe>.lock.ctl, the contender re-reads <exe>.lock inside the <exe>.lock.ctl critical section, re-verifies age > lockStaleAfter AND !isProcessAlive(meta.PID), removes/replaces <exe>.lock, and creates its own fresh <exe>.lock (with its new token, PID, and fresh created_at flushed to disk) before releasing <exe>.lock.ctl so a second racing evictor observes the first contender's fresh live-PID lock inside <exe>.lock.ctl and aborts eviction.
5. Release synchronized with ownership replacement via <exe>.lock.ctl (Thread 3): When the lock holder releases <exe>.lock, it acquires <exe>.lock.ctl (bounded by ctlLockWaitTimeout, aborting without unlinking <exe>.lock if <exe>.lock.ctl cannot be acquired) and performs the authoritative token read + comparison + os.Remove(lockPath) atomically inside the <exe>.lock.ctl critical section before verifying ctlToken and removing <exe>.lock.ctl, with an injectable test hook between initial unlocked token inspection and <exe>.lock.ctl acquisition so a replacement occurring between initial token read and unlink is detected and never unlinked.
6. go test -race ./internal/updater/... passes with TestUpdateConcurrentSwapsDoNotDeleteRollbackCopy, TestUpdateFailsWhenLockHeld, TestUpdateEvictsStaleLock, TestUpdatePausedLiveHolderNotEvictedPastStaleThreshold (paused-live-holder regression), TestUpdateTwoConcurrentStaleEvictorsSerialize (deterministic two-evictor regression), TestSwapLockReleaseInterleavedWithReplacementDoesNotDeleteNewOwnerLock (deterministic release-interleaved-with-replacement regression), and TestUpdateRecoverFromCrashedControlLockAndStalePrimaryLock (covering both dead-PID <exe>.lock.ctl + dead-PID <exe>.lock recovery AND fail-closed refusal when <exe>.lock.ctl is held by a live PID or has corrupt metadata).
