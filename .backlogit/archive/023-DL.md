# File overwrite configuration, --overwrite CLI flag, and interactive (Y)es | (N)o confirmation prompt (034-S)

## Problem Frame

<!-- BEGIN:problem-frame -->
Unify file overwrite behavior across directory (Dir) and explicit file (FilePath) capture modes with a single boolean configuration key (overwrite / file_overwrite, default false), per-meeting schedule override, --overwrite CLI flag, and interactive (Y)es | (N)o confirmation prompt that preserves pre-existing transcript (.md) and audio (.mp3) files untouched when declined or on rollback.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A (Selected): Single boolean overwrite config (with file_overwrite alias and per-meeting MeetingSchedule/scheduler.Entry override), --overwrite CLI flag across root/join/captions/schedule (forwarded via inheritedQueueFlags), uniform setupOutput existence check + ConfirmOverwrite callback + ErrOverwriteDeclined + pre-existing file rollback preservation, and interactive CLI promptOverwriteApproval('(Y)es | (N)o') on cmd.InOrStdin()/cmd.ErrOrStderr(). Option B: Separate flags/keys for transcript and audio overwrite. Option C: Keep implicit overwrite in FilePath mode and only prompt in Dir mode.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option A: Implement a single unified overwrite configuration, CLI flag, and interactive confirmation prompt across both Dir and FilePath modes, decomposing into 5 width-isolated tasks (034.001-T..034.005-T) under feature 034-F and shipment 034-S.
<!-- END:chosen-direction -->
