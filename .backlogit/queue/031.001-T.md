Implement high-speed (14x-100x real-time) audio-only fMP4 capture in internal/browser/recap.go and internal/browser/meeting_chrome.go for download-blocked SharePoint Meeting Recaps (g_fileInfo.isDownloadBlocked=true in streamembed.aspx):
1. Per-frame validated same-origin child iframe traversal (collectPlayerWindows, depth <= 3, skipping isAuthRedirectURL) before binding a per-player capture context.
2. Path A: WebCrypto AES-CBC (window.crypto.subtle.decrypt) + parallel oneDrive.transcode audio-segment fetch/decrypt (part=initsegment + part=mediasegment with track=audio&quality=audcopy, segmentTime=k*wsd up to ppd, 1 <= totalSegments <= 2400) with automatic Path B fallback and <video>.play() resumption.
3. Path B: MediaSource.prototype.addSourceBuffer/removeSourceBuffer + SourceBuffer.prototype.appendBuffer hooks with video/mp4 track stripping (EventTarget no-op SourceBuffer shim), tfdt-keyed deduplication/ordering (preserving dts === 0), muted 16x playbackRate, and currentTime stepping.
4. AudioContext.decodeAudioData to 44.1 kHz mono PCM, fixed-point transitive ParentID iframe scope (expandOwnedFrames), canonical VroomItemId priority in extractRecapTranscriptJS, and net/url-encoded recapItemID retention on chromeMeeting.

## Acceptance Criteria

* extractRecapAudioJS captures and decodes audio/mp4 (mp4a.40.2) fMP4 streams at 14x-100x real-time speed via Path A and Path B when g_fileInfo.isDownloadBlocked=true in streamembed.aspx.
* collectPlayerWindows validates each frame's own g_fileInfo identity before binding a per-player capture context, and restores all hooks/timers/AbortController in an idempotent finally block.
* expandOwnedFrames and isTargetInCaptureScope include nested OOPIFs (such as streamembed.aspx under xplatplugins.aspx) while excluding unowned tabs, and setLastErr preserves resource-limit and identity errors over isDownloadBlocked=true.
* chromeMeeting retains verified transcript VroomItemId (m.recapItemID) and attaches driveItemId via net/url when meetingURL lacks DriveItemID.
* go test -race ./internal/browser/..., go vet ./..., and golangci-lint run pass with zero findings.
