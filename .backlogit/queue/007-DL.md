<!-- BEGIN:options -->
- Option A: Add a third-party file-lock dependency such as gofrs/flock (rejected: violates the standard-library-only contract of internal/updater established in 005-DL / 016.002-T).
- Option B: Automatic stale-lock eviction/stealing of <exe>.lock or <exe>.lock.ctl based on age + PID liveness (rejected: two contenders inspecting an expired .lock or .lock.ctl can race so a delayed rename/unlink steals a newly acquired live lock, and OS PID reuse allows an unrelated process with the same PID to block age+PID eviction indefinitely while masking why the lock is stuck).
- Option C (chosen): Fail-closed standard-library atomic <exe>.lock via os.OpenFile(O_CREATE|O_EXCL|O_WRONLY, 0o600) with JSON owner metadata (pid, 128-bit hex token, created_at) and zero automatic eviction/stealing of <exe>.lock or <exe>.lock.ctl by contenders (<exe>.lock.ctl fails closed to manual control-lock cleanup so two competing control-lock contenders never steal a live .lock.ctl): canonicalize executablePath() by stripping any trailing .old or ' (deleted)' suffix when u.cfg.ExecutablePath == '' (so processes whose running image was renamed to <exe>.old derive the same canonical exe and <exe>.lock); resolve symlink targets (including dangling symlinks via parent dir + link target) so pre-swap os.Stat(exe)/filepath.EvalSymlinks(exe) wait-polling checks <target>.lock / <target>.old and performs one immediate re-probe of os.Stat(exe) before returning fs.ErrNotExist if neither marker is seen; record the pre-download target executable SHA-256/fingerprint when !force and revalidate it after acquiring <exe>.lock so swap aborts with ErrConcurrentUpdateModified / wrapped ErrUpdateLocked before renaming exe -> exe.old if a concurrent updater already replaced exe; contenders poll every lockPollInterval (default 50ms) up to lockWaitTimeout (default 15s) respecting caller ctx.Done() for acquisition/wait and never unlink, rename, or replace an existing <exe>.lock or <exe>.lock.ctl; on lockWaitTimeout expiry, contenders inspect <exe>.lock metadata, lockStaleAfter (default 2m), and injectable isProcessAlive(pid) purely for diagnostic classification in ErrUpdateLocked (distinguishing dead-PID orphaned lock, live-PID past lockStaleAfter noting paused holder or OS PID reuse, and active/corrupt/unreadable lock, each with manual recovery steps including restoring <exe>.old -> <exe> if <exe> is missing after a crash); acquireSwapLock(ctx, exe) returns (release func() error, err error) where release() uses an independent non-cancelable bounded cleanup context context.WithTimeout(context.WithoutCancel(ctx), u.ctlLockWaitTimeout) (default 2s, polling at ctlLockPollInterval=10ms, never canceled by caller ctx) around fail-closed <exe>.lock.ctl for authoritative token read + os.Remove(lockPath), swap returns errors.Join(swapErr, relErr), and Update sets res.Updated = true when rename(tmp, exe) succeeded on disk and only release() returned an error (while still returning the non-nil release error); and Windows locked-<exe>.old at swap entry aborts cleanly before moving the newly installed exe aside.
