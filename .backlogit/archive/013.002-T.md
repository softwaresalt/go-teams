Add teams.RedactURL and teams.RedactArgs in internal/teams/url.go, remove the raw queue line from splitQueueArgs unmatched-quote parse errors in internal/cli/queue.go, and apply URL redaction to ChromeRunner.run navigation error wrapping in internal/browser/runner.go (preserving the pre-allocation teams.ValidateMeetingURL(meetingURL) check in ChromeRunner.Join from 013.001-T) and batch queue argument logging in internal/cli/queue.go. Specification: (1) For a parseable HTTP/HTTPS URL with a non-empty host (u.Opaque == ""), clear u.User = nil, u.RawQuery = "", u.ForceQuery = false, u.Fragment = "", and u.Opaque = "" (keeping only normalized scheme://host/path). (2) For the malformed-URL / fallback path (when url.Parse fails, scheme is non-HTTP(S), u.Opaque != "", or u.Host == ""), do NOT simply slice up to ? or #; if the fallback cannot safely extract a clean scheme://host/path free of userinfo (@), query (?), and fragment (#), return a constant placeholder "[invalid-url]" (or strip any userinfo@ before the host in addition to stripping ?query and #fragment, and return "[invalid-url]" if any @, ?, #, or control character remains). (3) In internal/cli/queue.go, update splitQueueArgs(line string) to return fmt.Errorf("unterminated quote in queue line") without echoing the raw line so an unmatched quote on a passcode-bearing queue line never leaks the raw URL or ?p= passcode when runQueueFile propagates the error before tokenization/logging. Acceptance criteria: (a) ?p=secret-passcode, code=oauth, and #access_token=xyz never appear in RedactURL, RedactArgs, ValidateMeetingURL errors, ChromeRunner.Join pre-allocation validation and navigation errors (tested in internal/browser/runner_test.go), splitQueueArgs/runQueueFile parse errors, or queue logs; (b) Unit tests in internal/teams/url_test.go explicitly test RedactURL with embedded userinfo credentials on both a valid URL (https://user:pass@teams.microsoft.com/meet/123?p=tok#frag) and a malformed URL (https://user:pass@teams.microsoft.com:badport/meet/123?p=tok), asserting that neither user, pass, tok, nor frag ever appears in the output; (c) Unit tests in internal/cli/queue_test.go test an unmatched-quote queue line containing a ?p= passcode (e.g. join --url "https://teams.microsoft.com/meet/123?p=secret-passcode) and assert that the error returned from splitQueueArgs and runQueueFile contains neither the passcode nor the raw URL.
