# Live integration .env.local.test path expansion, legacy profile fallback, and remote headless Recap fixes (030-S)

## Problem Frame

<!-- BEGIN:problem-frame -->
Running the full test suite (including -tags=integration) against a real .env.local.test fails across four coupled surfaces: (1) .env.local.test path expansion (%VAR%, , ~) and go-teams -> teams-cli profile directory fallback are missing in internal/browser and internal/cli test loaders and browser profile resolution; (2) remote headless NewLiveMeeting uses chromedp.DefaultExecAllocatorOptions (which passes --password-store=basic and --use-mock-keychain, breaking Windows DPAPI cookie decryption) instead of launchCleanHeadedBrowser with --headless=new, and joinOnWebSel omits #openTeamsClientInBrowser; (3) SharePoint Meeting Recap g_fileInfo uses lowercase-d VroomItemId and returns text/html on isDownloadBlocked=true, causing decodeAudioData to fail; and (4) -tags=integration tests reject external %APPDATA% profiles and assume TEAMS_MEETING_URL is always an active live call rather than a /l/meetingrecap URL.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
- Option A (Recommended): 3-task width-isolated decomposition across internal/browser production (030.001-T), internal/browser integration/test helpers (030.002-T), and internal/cli integration/test helpers + recap unit tests (030.003-T)\n- Option B: Modify .env.local.test only and skip integration tests on /l/meetingrecap URLs
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option A: Fix internal/browser production profile resolution, clean --headless=new CDP routing for remote authenticated sessions, #openTeamsClientInBrowser selector, VroomItemId/isDownloadBlocked handling, and 2s CDP port release wait in 030.001-T; update internal/browser test env loader and integration tests in 030.002-T; and update internal/cli test env loader, CLI integration tests, and recap unit tests in 030.003-T.
<!-- END:chosen-direction -->
