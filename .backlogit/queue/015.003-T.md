Add deterministic browser-package unit tests for Recap MP3 audio capture, owned-frame recording-identity validation, and oversized-recording resource limits in `internal/browser/recap_retry_test.go` (Size: S | Complexity: low, domain: tests, posture: test-first, files: `internal/browser/recap_retry_test.go`).

Scope and approach:
1. In `internal/browser/recap_retry_test.go`, add:
   - `TestCaptureRecapAudioScopedToOwningMeetingPageAndEncodesMP3`: tests that `m.CaptureAudio(ctx, &buf)` on a recap `chromeMeeting` extracts audio strictly from scoped targets passing `isTargetInCaptureScope` whose recording identity matches `m.meetingURL`, ignores unrelated tabs, encodes valid non-empty MP3 bytes via `audio.NewEncoder` starting with an MPEG sync header, and returns `nil` finitely.
   - `TestCaptureRecapAudioRejectsOwnedFrameWithMismatchedRecordingIdentity`: explicit owned-frame recording-identity mismatch regression test proving that an owned frame whose URL or media source/metadata belongs to a different meeting recording (mismatching `recapExpectedIdentifiers(meetingURL)`) is rejected and never paired with the requested meeting's transcript.
   - `TestCaptureRecapAudioRejectsOversizedRecordingExceedingResourceCap`: deterministic regression test verifying that an oversized/long recording exceeding `maxRecapAudioSourceBytes` / `maxRecapAudioDurationSec` / `maxRecapAudioPCMBytes` is gracefully rejected with a clear `recap audio exceeds maximum supported size/duration` error before unbounded PCM/base64 allocation.
   - `TestCaptureRecapAudioReturnsErrorWhenNoAudioAvailable`: tests error return when no scoped target with matching recording identity provides recap audio.

Acceptance criteria:
1. `TestCaptureRecapAudioScopedToOwningMeetingPageAndEncodesMP3`, `TestCaptureRecapAudioRejectsOwnedFrameWithMismatchedRecordingIdentity`, `TestCaptureRecapAudioRejectsOversizedRecordingExceedingResourceCap`, and `TestCaptureRecapAudioReturnsErrorWhenNoAudioAvailable` pass under `go test -race ./internal/browser/...`.
