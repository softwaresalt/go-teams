<!-- BEGIN:description -->
Add a fail-closed, executable-keyed inter-process lock (<exe>.lock and release control lock <exe>.lock.ctl via os.OpenFile O_CREATE|O_EXCL|O_WRONLY, 0o600) with JSON owner metadata (pid, 128-bit hex token, created_at) written and flushed on creation, executablePath() preserving legitimate <name>.old filenames while failing closed with ErrConcurrentUpdateModified when u.cfg.ExecutablePath == '' and os.Executable()/EvalSymlinks resolves to ' (deleted)' or .old when filepath.Base(os.Args[0]) does not end in .old, dangling-symlink target resolution (<target>.lock / <target>.old) and one immediate os.Stat(exe) re-probe on transient absence, baseline snapshot capture at the very start of Update (marking concurrentSwapObserved=true if exe is missing or <exe>.lock/<exe>.old is present) plus under-lock installed-version / running-image identity verification inside swap when !force (aborting swap with ErrDowngrade / ErrConcurrentUpdateModified before renaming exe -> exe.old if another updater replaced or upgraded exe even before pre-download snapshot), bounded context-aware wait polling (lockPollInterval=50ms, lockWaitTimeout=15s) with zero automatic eviction or stealing of <exe>.lock or <exe>.lock.ctl by contenders, diagnostic ErrUpdateLocked classification on timeout via lockStaleAfter (default 2m) and injectable isProcessAlive(pid) (distinguishing dead-PID orphaned lock, live-PID past lockStaleAfter noting paused holder or OS PID reuse, and active/corrupt/unreadable lock with manual recovery steps including restoring <exe>.old -> <exe> if <exe> is missing), error-returning release() (func() error) using an independent non-cancelable cleanup context context.WithTimeout(context.WithoutCancel(ctx), u.ctlLockWaitTimeout) (2s, ctlLockPollInterval=10ms) around fail-closed <exe>.lock.ctl token-verified unlock joined via errors.Join(swapErr, relErr) (with Update setting res.Updated = true while still returning the non-nil release error if rename(tmp, exe) succeeded on disk and only release() failed), and clean abort at stale <exe>.old removal when <exe>.old is locked by a running Windows process around Updater.swap in internal/updater so two concurrent teams-cli update processes cannot delete each other's <exe>.old rollback copy.
