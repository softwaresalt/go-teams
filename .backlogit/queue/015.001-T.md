Implement post-meeting Recap audio extraction and MP3 encoding in `internal/browser/recap.go` and `internal/browser/meeting_chrome.go` (Size: S | Complexity: medium, domain: code, posture: test-first, files: `internal/browser/recap.go`, `internal/browser/meeting_chrome.go`).

Scope and approach:
1. In `internal/browser/recap.go`, add `extractRecapAudioJS`, configurable resource-limit package variables (`maxRecapAudioSourceBytes = 64 * 1024 * 1024` / 64 MiB compressed media blob cap, `maxRecapAudioDurationSec = 1800`, and `maxRecapAudioPCMBytes = 128 * 1024 * 1024` decoded PCM cap), and `captureRecapAudioFromTargets(ctx context.Context, cdpPort int, boundTargetID string, meetingURL string, w io.Writer) error` (invoked with `m.meetingURL` from `(*chromeMeeting).captureRecapAudio`):
   - Queries `listCDPTargets(cdpPort)`, resolves `ownedFrames` via `fetchOwnedFrames`, and filters targets strictly through `isTargetInCaptureScope(t, boundTargetID, ownedFrames)`.
   - Uses `recapExpectedIdentifiers(meetingURL)` (matching the transcript path's `targetMatchesIdentifiers` / `payloadMatchesIdentifiers` and `parseRecapPayloadForMeeting` discipline) to validate before extraction that the owned target/frame's `t.URL` and extracted media source URL / page metadata (`pageUrl`, `fileName`, `itemId`, `mediaUrl`) match the expected meeting recording identity when `recapExpectedIdentifiers(meetingURL)` is non-empty, skipping owned frames whose URL or media source mismatches the expected recording identity.
   - Enforces bounded decoding and transfer in `extractRecapAudioJS` and `captureRecapAudioFromTargets`: checks `Content-Length` and streamed reader byte count against `maxRecapAudioSourceBytes` before calling `decodeAudioData`, checks `audioBuffer.duration` (`<= maxRecapAudioDurationSec`) and decoded PCM byte length (`<= maxRecapAudioPCMBytes`) before allocating `Int16Array` / base64 chunks, transfers/decodes in bounded windows, and rejects recordings exceeding the cap with a clear structured error (`recap audio exceeds maximum supported size/duration`) before allocating unbounded PCM/base64 buffers.
   - Decodes each validated 44.1 kHz mono `int16` base64 PCM chunk with `decodeAudioPayload` (enforcing `maxRecapAudioPCMBytes`) and encodes to MP3 via `audio.NewEncoder(w, audio.SampleRate)` (`WritePCM` + `Flush()`).
2. In `internal/browser/meeting_chrome.go`, persist `m.cdpPort = port` in `joinHeaded` after `launchCleanHeadedBrowser` succeeds, and update `(*chromeMeeting).CaptureAudio(ctx context.Context, w io.Writer)` to branch on `if m.IsRecap()` and invoke `m.captureRecapAudio(ctx, w)` (passing `m.meetingURL` to `captureRecapAudioFromTargets`) so Recap audio capture completes finitely.

Acceptance criteria:
1. `captureRecapAudioFromTargets(ctx, cdpPort, boundTargetID, meetingURL, w)` inspects only CDP targets passing `isTargetInCaptureScope(t, boundTargetID, ownedFrames)`, validates expected recording identity via `recapExpectedIdentifiers(meetingURL)` (`targetMatchesIdentifiers` / `payloadMatchesIdentifiers`) before extracting audio, skips mismatched owned frames, and encodes mono 44.1 kHz `int16` PCM through `audio.NewEncoder(w, audio.SampleRate)` (`WritePCM` + `Flush()`).
2. `extractRecapAudioJS` and `captureRecapAudioFromTargets` enforce `maxRecapAudioSourceBytes` (`64 MiB`), `maxRecapAudioDurationSec` (`1800`), and `maxRecapAudioPCMBytes` (`128 MiB`) before allocating unbounded PCM/base64 buffers, returning a structured `recap audio exceeds maximum supported size/duration` error when exceeded.
3. `joinHeaded` stores `m.cdpPort = port` so post-`Join` `CaptureAudio` has the active DevTools port in both headed and headless modes.
4. `(*chromeMeeting).CaptureAudio` in Recap mode (`m.IsRecap() == true`) writes valid MP3 frames to `w` and returns `nil` finitely without blocking for `ctx.Done()`, or returns a descriptive error when no matching Recap audio source is available or the recording exceeds the resource cap.
5. `go build ./...` and `go vet ./...` pass cleanly. Source stash: DF1F461F.
