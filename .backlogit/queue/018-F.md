<!-- BEGIN:description -->
Add an executable-keyed inter-process lock (<exe>.lock via os.OpenFile O_CREATE|O_EXCL|O_WRONLY, 0o600) with JSON owner metadata (pid, random token, created_at), bounded context-aware wait polling (returning ErrUpdateLocked on timeout), crash-safe stale-lock eviction after lockStaleAfter, and token-verified release around Updater.swap in internal/updater so two concurrent teams-cli update processes cannot delete each other's <exe>.old rollback copy. Source stash: 2D0BAA19 (shipment 016-S, feature 016-F, task 016.002-T, PR #40, review thread PRRT_kwDOTStvas62SjnB); deliberation: 007-DL (docs/decisions/2026-11-11-update-interprocess-lock-deliberation.md); plan: docs/plans/2026-11-11-update-interprocess-lock-plan.md.
<!-- END:description -->

<!-- BEGIN:dod -->
1. internal/updater uses only the Go standard library and internal/version (zero new external dependencies in go.mod).
2. Concurrent Updater.Update executions on the same executable path serialize cleanly without deleting each other's <exe>.old rollback copy, fail closed with ErrUpdateLocked on lock timeout, and evict stale locks safely.
3. go test -race ./..., go vet ./..., go vet -tags=integration ./..., and golangci-lint run pass with zero findings.
<!-- END:dod -->

<!-- BEGIN:goals -->
1. Serialize the entire Updater.swap lifecycle (stale .old removal, exe -> .old rename, tmp -> exe rename, rollback .old -> exe on failure, and post-swap .old cleanup) across concurrent OS processes using a standard-library <exe>.lock lockfile.
2. Self-heal stale lockfiles left by crashed update processes after lockStaleAfter without deleting in-flight or newly acquired locks.
3. Verify ErrUpdateLocked propagation and concurrent update serialization in internal/updater and internal/cli unit tests under -race.
