## Verified correct

- Correctness review confirmed `encoderTailSlack=4` is sufficient: the internal
  read pointer reaches at most index `len+1` (right channel offset 1 + one stride
  past), so cap must be `≥ len+2`; 4 gives 2× margin, independent of frame count.
- shine-mp3's `Write` loops on `len(data)`, not cap, so the slack changes nothing
  about which samples are encoded → **output byte-identical**.
- `raceDetectorEnabled` is referenced nowhere after removing the skip guards;
  deleting `race.go`/`norace.go` is safe.

## Decision rationale

shine-mp3 is `NOASSERTION`-licensed, so vendoring/forking to patch the `unsafe`
was rejected (copyright risk). The capacity-slack fix resolves the `-race`
checkptr fault and keeps the pointer in a valid allocation **without modifying
shine-mp3** and with identical output — the lowest-risk resolution.
