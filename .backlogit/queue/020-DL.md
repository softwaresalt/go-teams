# High-speed audio-only MP3 capture on download-blocked SharePoint Meeting Recaps (031-S)

## Problem Frame

<!-- BEGIN:problem-frame -->
When SharePoint Meeting Recaps set g_fileInfo.isDownloadBlocked=true in streamembed.aspx, direct raw media download URLs return HTTP 403 or text/html error pages and <video src='blob:...'> cannot be fetched directly. Operators using go-teams with --audio / --recap-audio need fast (14x-100x real-time) audio-only MP3 capture from the authorized in-page stream without downloading video or relying on external tools.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
- Option A: Dual-path in-browser WebCrypto AES-CBC parallel oneDrive.transcode audio-segment fetch/decrypt (50x-100x) + MSE MediaSource/SourceBuffer hook with video/mp4 stripping, muted 16x playbackRate, and currentTime stepping (14x-40x), decoded via AudioContext.decodeAudioData to 44.1 kHz mono PCM and encoded to MP3 via internal/audio.Encoder (Recommended)\n- Option B: Real-time 1x getDisplayMedia tab-audio recording during full playback\n- Option C: External ffmpeg/yt-dlp subprocess pipeline
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Select Option A: decompose 031-F into three width-isolated tasks (031.001-T code in internal/browser, 031.002-T tests in internal/browser, 031.003-T docs in docs/) packaged into shipment 031-S, sequenced immediately before 010-S.
