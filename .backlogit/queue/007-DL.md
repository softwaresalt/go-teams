- Option A: Add a third-party file-lock dependency such as gofrs/flock (rejected: violates the standard-library-only contract of internal/updater established in 005-DL / 016.002-T).
- Option B: Bare O_CREATE|O_EXCL lockfile without wait polling or stale-lock eviction (rejected: a crashed update process permanently wedges future updates, and concurrent processes fail immediately instead of serializing across the brief swap).
- Option C (chosen): Standard-library atomic <exe>.lock via os.OpenFile(O_CREATE|O_EXCL|O_WRONLY, 0o600) with JSON owner metadata (pid, 128-bit hex token, created_at), bounded context-aware wait polling (returning ErrUpdateLocked on timeout), dead-holder liveness proof via injectable isProcessAlive(pid) (failing closed to alive=true whenever pid<=0, metadata is unreadable/corrupt, or liveness cannot be disproved so an expired lock of a live/paused holder is never evicted), and crash-safe exclusive control lock <exe>.lock.ctl (writing/flushing its own {pid, token, created_at} metadata, acquired under bounded ctlLockWaitTimeout=2s / ctlLockPollInterval=10ms, recovering a dead-owner expired <exe>.lock.ctl after ctlLockStaleAfter=5s when ctlMeta.PID > 0 and !isProcessAlive(ctlMeta.PID) via atomic rename to <exe>.lock.ctl.stale.<token> + remove + retry, failing closed with ErrUpdateLocked when <exe>.lock.ctl is live or unreadable/corrupt, aborting primary-lock unlink if release cannot acquire <exe>.lock.ctl, and verifying ctlToken before removing <exe>.lock.ctl) serializing both stale-lock recovery (re-reading <exe>.lock, re-verifying age > lockStaleAfter AND !isProcessAlive(meta.PID), and writing/flushing the new owner's <exe>.lock inside <exe>.lock.ctl before releasing <exe>.lock.ctl) and authoritative token-verified release (atomic token read + comparison + os.Remove(lockPath) inside <exe>.lock.ctl), verified by TestUpdateRecoverFromCrashedControlLockAndStalePrimaryLock.
